## 左侧菜单（slider-menu）改造为圆角卡片样式

**需求**：按用户提供的截图，把首页左侧二级分类菜单从「通铺灰块」改成「圆角卡片 + 选中态高亮卡片」。

**改动文件**

- `src/pages/index/components/slider-menu.vue`
- `src/pages/order-system/category/components/slider-menu.vue`（与上面逐字节相同的副本，已同步）
- `src/pages/index/index.vue` / `src/pages/order-system/category/category.vue`：`.goods-sidebar` 背景 `#f7f8fa` → `#fff`

**最终取值（从截图 196×890 像素采样换算，侧栏 175px ⇔ 200rpx，即 1rpx = 0.875px）**

- 卡片：`176rpx` 宽、左右 `12rpx`、圆角 `12rpx`、间距 `16rpx`、`padding: 10rpx 8rpx`、`line-height: 42rpx`、底色 `#f5f5f5`、文字 `#333`
- 选中态：`#5ac3f3` 底 + 白字（用户选择沿用项目蓝，而非截图里的红 `#e72514`）
- 去掉了组件库默认选中态左侧 4px 竖条（`--wot-sidebar-active-border-width: 0`）
- `wd-sidebar` 加 `important-h-auto`，让 `__padding` 撑高为 0，避免它把灰底画出来

**踩坑记录（重要）**

1. wot-design-uni 实际安装的是 **1.14.0**（`package.json` 写的 `^1.4.0` 被 caret 拉高了），CSS 变量前缀已从 `--wd-` 改为 `--wot-`，**代码里原有的 `--wd-sidebar-active-color: #5ac3f3` 一直是失效的**（选中态实际显示组件库默认蓝 `#4d80f0`）。
2. 本项目里 **不要用 `<script>` 字符串里含 `#` 的 uno 颜色类**（如 `'important-bg-#f5f5f5'`）。构建链路会把 class 串里的 `#` 转义成 `_a_`，但 uno 侧不同步，导致 `#f5f5f5`、`#333` 这类规则被静默丢弃且不报错。模板属性里的 `color-#fff` 是正常的。
   → 因此选中/未选中配色改为走 `custom-style` 内联样式（`#` 在内联样式里不受转义影响，且避开 uno 产物 `rgb(r g b / var(...))` 的老 iOS 兼容问题）。
3. 组件库 `.wd-sidebar-item` 的 `white-space: wrap` 是非法值（等同 `normal`），分类名里的换行符会被吃掉；已加 `important-whitespace-pre-line`。
4. 用 `important-` 前缀的 uno 类是最可靠的覆盖手段：它们编译进 `app.wxss`（全局生效，能进任何组件），且带 `!important` 可以盖住组件库的 scoped 规则。组件自己的 `<style>` 块编译成组件级 wxss，能否作用到子组件内部不确定，别依赖。

**验证方式**：`pnpm build:mp-weixin` 通过；逐个 grep `dist/build/mp-weixin/app.wxss` 确认用到的类都已生成（`important-bg-#f5f5f5` / `important-color-#333` 就是在这个环节发现缺失的）。
